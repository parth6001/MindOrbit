# Release

## Debug Installation

Build with `gradlew.bat assembleDebug`. Install `app/build/outputs/apk/debug/app-debug.apk` with `adb install -r`. Debug builds are signed with the Android development key and are debuggable; they are intended for testing and personal evaluation.

## Production Signing

No production signing credentials were supplied. No production key or password is generated by this project. The release build has code shrinking enabled and is unsigned until the owner configures signing.

Use Android Studio's Build > Generate Signed App Bundle / APK > APK workflow. Create a private keystore outside the repository, choose a strong unique password in the interactive dialog, and store the key/password in a secure vault with a separate backup. Do not paste passwords into shell commands, source files, Gradle files or version control. Keystores and keystore.properties are ignored by .gitignore.

After configuring signing locally, build `assembleRelease`, verify with `apksigner verify --verbose --print-certs`, and inspect the merged manifest. A production update must keep applicationId app.mindorbit and use the same signing key. Increase versionCode for each release. A production-signed build cannot update a differently signed debug install; export local data before uninstalling that install.

## Release Gate

Run clean, test, lint, assembleDebug, connectedDebugAndroidTest and release lint. Inspect permissions with aapt2 or apkanalyzer, verify that INTERNET is absent, review exported components, and inspect runtime dependencies. Install on Android 13 and a current Android version. Check notification denial, exact access denial, channel mute, reboot, timezone change, Doze, force-stop recovery, alarm presentation, backup restoration, large-font layouts, and OEM battery restrictions.

Do not claim store readiness from a successful compilation alone. See TESTING.md and SECURITY.md for the checks actually completed in this workspace.
